# PRD 0.5 功能实现与回归记录

日期：2026-10-25。依据 [PRD 0.5](prd-family-intervention.md)，承接[首批交互实现](prd-implementation-2026-10-24.md)。本版汇总此前保留在云端工作区的实现与修复，供代码评审和本机使用；没有部署、转换生产数据库或读取生产业务数据。历史交接快照不代表本版进度。

## 已实现的范围

- 独立新模型及 API 契约门禁，共用 Rust 业务规则；原生 SQLite 和 Rust Worker／SQLite Durable Object 两种运行方式。目标、方法、课程目录、课记、家庭干预、知识、反馈、复盘、行动、观察和测量均保留版本与明确关系。
- 今天页两个主入口、长期关注详情、当天计划／总结切换、多个计划显式选择、跨日期本机草稿恢复和到期回看入口。
- 课程／老师按稳定 ID 维护新增、改名、停用、恢复；历史名称快照保留。基础课记快速提交、可选观察、家人整理关系／知识／下一步、独立分区并发写入、窄范围撤销、管理员删除及来源引用保护。
- 家庭计划保存为共享草稿，之后填写实际目标表现、明确实际方法及版本；可在计划／总结就地新建。经验、困难、反馈与行动随总结原子保存；修订保留历史，删除来源不丢失已经沉淀的跟进。
- 目标与方法详情关联知识、困难、行动及历史实际记录；方法使用按家庭／机构、版本及最近时间展示。计划候选项和知识提示按状态筛选，编辑期间不被刷新重排。
- 经验实践主结果、明确修订与他人附注分开；困难可比观察按帮助条件、明确调整与方法版本分期。统一家庭周末日程、复盘证据分页、已查看版本、多人冲突、批次恢复／收尾及后续行动维护。
- 家庭／机构／合计覆盖、目标层级快照去重、固定色阶、自然月教师节数、月份切换、日历完成／待总结区分、目标时间分布、方法实际使用及参与信号的明确范围。
- 独立瞬间观察、共享需要说明、指标版本与实际测量；测量按可比条件分组，覆盖次数不冒充能力达成率。可编辑的家人摘要预览不自动发送。
- 基础课记离线队列及目录依赖、原账号／空间校验、精确重放；通用字段引导、可搜索关系选择、大字模式、日期双方式、覆盖层返回、桌面入口元数据及可选受信任设备登录。
- 新模型 Excel 导出、腾讯工作簿显式映射／去重／来源保留，以及旧库维护转换／受限回滚工具。具体边界见[数据转换与导入](prd-data-transition.md)。

## 最近三轮核查修复

在上述功能上继续核对了计划知识筛选、候选项冻结、模板引导、方法使用概况、行动版本、反例展示、复盘批次恢复、历史分页、已展开依据、目标局部观察和日历点击等缺口。

最后一轮另外实际复现并修复：

1. 同账号多个窗口按整张草稿映射保存会互相覆盖。改为按记录合并保存意图；冲突副本持久保留，可在刷新后显式核对和恢复，涵盖目标／方法、课记、干预、跟进和观察。
2. 另一窗口切换 Cookie 后，旧表单可能以新账号提交。请求绑定期望身份／空间，由共用 Rust 事务层核对实际会话；读取、写入、导出及回执重放均受校验。身份头不授予权限。
3. 目标／方法修改省略可选字段会误清空原值。保留未提供字段，空字符串／null／false 仍是明确修改；内部 HTTP→DO 转发保留字段存在性，幂等标识区分两者，旧确认回执仍能重放。
4. 保存已完成但响应丢失后，认证／空间／页面版本拒绝重试会丢弃原请求。现在保留原操作编号和完整请求，原账号恢复后仍核对同一次操作；明确业务校验失败仍允许修改。
5. 等候本机保存时重新登录，旧异步任务可能读取新全局身份继续发送。现在在等待前捕获登录代次、发送前再核对，变化即停止旧发送，保留原账号填写。

浏览器回归还修正了两处过早读取保存结果的测试等待条件：等待准确命名的编辑器关闭，再核对服务器，不用保存前后都可能为1的可见弹层数量充当完成证据。

## 本机使用与发布边界

先按[开发说明](development.md)准备 Node、Rust 和依赖，再执行 `npm run web:build`。新模型使用 `bash tools/start-prd-local.sh`，默认独立数据库为 `.local/prd-development.db`，关闭示例数据并要求登录。首次建库可通过同一脚本的 `admin-init --username owner --name 家人管理员 --password-stdin` 子命令，从标准输入创建本机管理员；不要在命令或仓库里填写密码。

旧模型仍是普通启动的默认值。本机新库测试不自动改变现有数据库；不要仅修改 `SKARMA_MODEL` 升级旧库。生产转换、私密配置与真实数据对账按[维护流程](prd-data-transition.md)另行操作。本次只提交并推送代码，不部署、不修改原 Worker／DO／空间／域名或管理员。
