# 手机界面减负实现与复验

2026-10-27，用户在[独立评审](interface-review-2026-10-26.md)后要求继续实现。
以`17449ad`为代码基线，保留已有评审文档与截图，完成本轮界面调整。

## 已实现

| 评审问题 | 本轮调整 |
| --- | --- |
| UI-01 目标首屏被筛选占满 | 新建入口置于标题旁；搜索后只显示筛选摘要；期限／来源／窗口／展示方式主动展开；卡片先显示名称、状态、覆盖和关联数 |
| UI-02 已选目标仍在推荐后面 | 选定后收起推荐；先呈现已选目标，困难和经验各留一句；目标笔记、历史依据和待做行动从“目标笔记与参考”展开 |
| UI-03 总结先重复计划 | 先填写实际目标及表现，再明确实际方法；角色、原计划和已有经验反馈分别展开；困难／经验重点仍可见 |
| UI-04 方法必填项被目录挤走 | 名称、具体做法、关联目标入口靠前；目录主动打开；说明和管理分组；目标关联仍明确保存 |
| UI-05 成功确认在很下面 | 确认及“补充课堂观察／完成”移到当天记录和待办之前；保留待上传、失败和不确定状态 |
| UI-06 引导重复 | 标签常驻、短示例留在输入框；问句和完整例子在标签旁主动展开；下拉不重复通用问句；常规状态精简为“草稿已存本机” |
| UI-07 新建沿用管理表单 | 新建／编辑按经验或困难明确命名；新建不问修改原因；条件、状态和手动日期可展开；经验阶段仍必须明确选择 |
| UI-08 空依据复盘过重 | 精简空状态；比较说明和日程分组；实际已加载证据直接展示；单对象按钮叫“保存复盘”，队列才叫“保存并下一项” |
| UI-09 列表和管理混在一起 | 目标／方法点击标题看详情、同行编辑；列表用关联数量代替全部原文；跟进工具收起，完整关联仍在详情与执行上下文 |
| UI-10 桌面空间利用 | 内容限宽1080px，主操作同行，筛选默认收起；本轮沿用同一导航与列表，没有新建桌面详情导航栈 |

新增共享`Disclosure`通过显示状态收起内容，保留子组件挂载；折叠不清空输入，也不生成额外业务状态。
原有API、ID、版本、幂等、统计口径、权限和数据库结构没有修改。

## 验证

- 类型检查、Web构建通过；没有新增依赖。
- 客户端55项、规划14项、工作流6项、同步14项通过；37项交接产物SHA校验通过。
- **22个真实浏览器脚本全部通过**：原21组功能回归，加`smoke_prd_simplified_web.py`。
  新专项已加入`npm run test:prd-web`默认入口。
- 目标页在390×844、360×640、1440×900检查新建入口及首条目标可见、无横向溢出；
  总结在390×844和360×640检查实际表现输入框完整可见。
- 新专项用普通成员通过真实接口验证：筛选折叠后保留、方法明确关联、可选信息折叠后实际保存、
  计划笔记保留、正式总结`unknown`不生成实际方法、多个当天记录时确认仍在首屏、
  新建经验显式阶段与关联、复盘家人感受实际写入。
- 既有回归保留双成员冲突、丢响应重试、多窗口草稿、账号切换保护、原关联与历史、
  课程／家庭计数、测量分段、导入导出、待办与复盘分页及后台刷新等业务断言。
  需要折叠内容时，测试通过真实`aria-controls`入口展开；可见性断言没有自动展开。
  不再要求列表展开全部关联原文或问句常驻。
- 回归实际发现：重排补充区时，历史复盘修订暂时失去了家人感受编辑入口。
  已将其从仅新复盘的日程分支移出；`completion`中的历史修订和并发对照场景通过。

测试仅使用独立合成SQLite库。没有重跑或冒称新增Rust／DO验证；本轮没有更改后端。
此前双运行环境验证和发布记录保留原出处。
