# 中国大陆用户的访问入口评估

日期：2026-10-19，Asia/Singapore。用户明确主要使用者位于中国大陆，先解决无需代理
访问的问题；暂停新的云端应用发布。“今天 → 长期关注”置顶已在本地完成，类型检查与
Web 构建通过，尚未发布。当前线上 Cloudflare 版本保持原样。

## 当前证据与边界

- 现有完整 Worker 经管理员 Mac 的 HTTP 代理访问，`/api/health` 返回 200 / `status=ok`。
- Mac 当前普通域名解析异常，需与 Cloudflare 公共 DNS 对照；该事实不能推广成全国
  所有网络的统一结论。
- Mac 同时存在 FlClash TUN 路由。即使给 curl 加 `--noproxy`，流量也可能经过 TUN，
  因此不能把之前的成功请求写成“大陆无代理可用”。
- 用户报告大陆访问失败，尚无三个运营商、不同地区的完整无代理验收。线上功能健康
  与目标用户能连上，需要分别确认。

## 可选路径

自有域名并非所有部署路线的必要条件。支持完整后端与持久数据的平台可以提供默认
HTTPS 子域名；可先验证平台入口，再决定是否购买域名。候选与使用限制见
[默认 HTTPS 平台核对](default-https-platforms.md)。平台地址本身不保证大陆可达。

用户进一步要求长期不购买域名与服务器，并提出客户端同步方向；新增
[免自有基础设施方案调研](no-owned-infrastructure-research.md)，比较原生 App + 用户网盘、
微信小程序 + 云开发内置调用、CloudKit 及免费后端。免费测试网址不自动等于可生产入口。

| 路径 | 对现有实例的影响 | 准备与成本类别 | 适用判断 |
| --- | --- | --- | --- |
| 平台默认 HTTPS 地址 → 完整应用托管 | 需要部署原生应用、配置持久数据，并受控迁移当前 CF 数据 | 平台计算、磁盘与流量费用；核对默认域名使用条件 | 不需要先买域名；优先检查 Sealos，另有 Railway、Render 等候选，均待实际大陆验收 |
| 自有域名 → 当前 Cloudflare Worker | 可以保持同一 Worker / DO 和现有账号数据 | 域名年费，接入 Cloudflare DNS，配置证书与精确应用来源 | 变更较小，适合先验证；不能承诺大陆各运营商稳定可达 |
| 自有域名 → 香港云上的原生应用 | 需配置主机、HTTPS、持久存储，并受控迁移当前云端数据 | 域名与主机费用；按接入商说明，香港服务器不属于大陆服务器备案场景 | 不愿等待大陆备案时可评估；跨境路径与时延仍需实际测试 |
| 自有域名 → 大陆云上的原生应用 | 需部署和数据迁移，已有 Rust / SQLite 原生入口可复用 | 域名与主机费用，办理 ICP 备案及接入商要求 | 主要用户在大陆、以长期稳定访问为首要目标时更适合评估 |

后两项是部署判断，不是对任何套餐或跨网质量的保证。未购买域名、主机或付费计划。

## 保留 Cloudflare 的具体做法

[Cloudflare 官方 workers.dev 说明](https://developers.cloudflare.com/workers/configuration/routing/workers-dev/)
建议正式应用使用 Worker route 或 Custom Domain。绑定自有域名需要一个处于激活状态、
由自己管理的 Cloudflare zone；平台可为 Custom Domain 创建 DNS 记录和证书，见
[官方配置步骤](https://developers.cloudflare.com/workers/configuration/routing/custom-domains/)。

可先选一个自己的域名，将例如 `app.example.com` 绑定到现有完整 Worker，保持同一个
Worker、`SkarmaSpace` 绑定和 `SKARMA_SPACE`。精确允许新 HTTPS 来源，随后通过新域名
重新登录。此前“没有自有域名”的约束仍然有效，需要先取得一个可管理域名。

自有域名能改变访问使用的主机名，但不等于拥有大陆节点，也不会自动消除跨境网络和
Cloudflare 边缘 IP 的可达性问题。它是一个可以验证的候选入口，不是大陆可用性承诺。
仅把前端换到别处而仍让浏览器直连不可达的 API 域名，也无法完成登录与保存流程。

Cloudflare 中国网络要求 Enterprise、单独订阅及 ICP / 内容审核条件，见
[官方入门](https://developers.cloudflare.com/china-network/get-started/)。普通免费 Worker
绑定域名不等于已开通该网络。其[产品清单](https://developers.cloudflare.com/china-network/reference/available-products/)
未明确列出当前使用的 SQLite Durable Object，不能未经供应商确认就假定整套数据能力
原样适用；不将此企业方案作为当前低成本起步路径。

## 香港与大陆部署的备案边界

[腾讯云官方备案说明](https://cloud.tencent.com/act/pro/mobile-beian)区分中国大陆资源与
中国香港／境外资源。香港服务器不用于大陆服务器备案；使用大陆云资源提供网站服务时，
需要按接入商和主管部门要求办理备案。注册域名本身与服务器接入备案是不同步骤。
如果以后接入包含大陆节点的 CDN，还要重新核对该产品的接入与备案条件。

## 上线验收方式

1. 在用户真实使用地区，用移动、联通、电信的普通网络，关闭测试设备的 HTTP/SOCKS
   代理及会接管流量的 TUN / VPN，分别记录网络状态。应由设备持有人完成其网络切换。
2. 分别验证 DNS、HTTPS 首页、实际 JS 资源和 `/api/health`。保留证书验证。
3. 由持有人登录，检查读取、保存本人可访问的记录和重新打开页面；只成功打开静态
   首页不足以证明应用可用。
4. 对比 Wi-Fi、蜂窝和不同时段，记录时延、失败比例与错误码。不要把携带 Cookie、
   密码或个人记录的完整 HAR / 原始日志公开上传。
5. 候选入口通过后再确定正式入口是否使用平台地址或自有域名，最后合并待发布的界面变更并发布。未通过时在
   香港／大陆托管路径中选择下一步，不能通过要求家人安装代理代替验收。

## 建议

若希望先保留已有 Cloudflare 实例并尽量少改动，可先用自有域名作大陆无代理验证。
若要求面向大陆用户长期稳定运营，优先评估大陆云与备案；暂不备案时评估香港云。
选择、费用和目标域名确定后，再执行接入或迁移。此文仅评估，未改线上入口。
