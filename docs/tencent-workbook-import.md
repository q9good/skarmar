# 腾讯文档 Excel / CSV 导入

日期：2026-10-19。此功能在管理员账号页面提供上传、映射预览和确认写入。
当前实现是有限范围的历史资料导入，不是腾讯多维表的完整关系迁移；上线与真实数据验收
以开发交接为准。原导入工作区在 `.local/import-wip-snapshot-20261019/` 留有代码与哈希快照，
原工作区未被重置或覆盖。

## 支持范围

| 工作表 | 处理方式 |
| --- | --- |
| 目标总表、阶段目标、目标 | 导入目标；层级、领域、标准、状态、归档和起止日期按预览映射 |
| 每日训练记录、训练记录 | 导入已完成的历史训练；保留重点、观察、问题及下一步原文 |
| 使用说明 | 明确显示为原始资料存档，不生成业务实体 |
| 其他尚未确认的工作表 | 阻止整批写入，要求核对映射；不静默存档 |

目标无层级列时会明确提示按历史短期目标导入，不推断父级。历史训练不补造目标角色、
逐目标结果、快照或经验；问题原文保留在训练中，不自动生成独立困难。来源中额外未映射
列保留在私有原始行，预览逐列显示识别情况。“记录人”和“训练形式”同时附在观察备注，
不会自动建立成员或推断授课老师；目标的“关联／关联 2”原文附在复盘备注，不推断主辅角色。
目标编号可用于稳定来源 ID。训练观察为空的行不能作为已完成记录导入，即使填写了记录人。
困难、经验及源关联的完整业务映射仍需有效关系核对，不得将页面显示“导入完成”等同于
整个多维表关系迁移完毕。

源文件缺少层级或有不完整行时，先让持有人确认处理规则，再准备私有导入副本：只补充
已确认的层级，将明确排除的行清空但保留其他行的原坐标，不压缩或重排行号。原文件保持
不变，私下保存两份文件的 SHA-256、变更决策及逐单元格对照结果。导入后再次核对时使用
同一副本；不要直接重新上传字段不同的原文件绕过去重保护。真实文件与决策明细不进入 Git。

预览和结果同时显示业务记录与原始存档的数量；总新增行数包含说明等存档行，不能视为
训练记录数量。

## 文件和确认流程

1. 导出当前完整 `.xlsx`，或按表分别导出 UTF-8 `.csv`；保留原表名、字段名、日期、枚举
   和可用的来源记录 ID。不要只导出筛选后的当前视图。
2. 管理员在“我的账号”选择文件。选择发生在本机；“上传并预览”才向本空间服务器发送。
3. 核对每表、每列、示例、计数和告警。预览不会写目标、训练等业务记录。
4. 没有无效行、存在可识别的业务行且有新增内容时，勾选确认并导入。
5. 保存批次编号，并按新记录及原始资料对账。源表保留作历史对照。

只支持浏览器上传，每次一个文件。文件上限 10 MiB，最多 20 表、10,000 数据行、100 列；
单元格最多 20,000 字符，解析后的整批 JSON 最多 1,000,000 字节。超限应按表或日期分批。
每行附带表头的原始资料存档合计最多 4 MB，过大时也须分批。
Excel ZIP 内部文件最多 1,000 项，总声明解压大小最多 64 MiB。损坏、非 UTF-8 CSV、
重名／同义列冲突、缺少必需列或无效日期会报告错误，不截断正文。

## 来源、去重和安全边界

- 当前来源文档标识为 `DVENwZGhrRUpka2xN`；不是通用的任意文档同步接口。
- 优先以来源文档、工作表和来源记录 ID 建立映射；无 ID 时明确告警并用行号。源表重排
  后不能凭行号保证同一记录，请先人工核对。
- 相同来源与相同原文再次导入会跳过；同一来源内容变化或已有同名目标会阻止写入，
  不覆盖现有业务修改。当前不支持自动更新，预览中的 updated 恒为零。
- 每个预览属于创建它的管理员，有效期一小时；最多保留每位管理员近期三份有效预览。
  过期预览在后续预览请求时清理，不承诺时间到即后台删除。已提交原始行保存在私有数据库。
- 普通成员、匿名请求、过期会话、其他管理员的未提交预览都不能用于导入。
- 同一批次重试返回原结果；写入在原生 SQLite / DO 事务中完成，后续 SQL 失败整批回滚。
- 真实文件、正文、数据库、凭证和原始响应不进入 Git 或测试夹具。

## Cloudflare 与迁移

普通 Worker 只接收 multipart 和验证入口权限；文件以原始字节送入同一空间的私有
Durable Object，在再次验证管理员后解压和解析。内部上传路径只接受 import-authorize
证明，不接受任意命令。原生环境在阻塞任务中解析，避免占用异步请求执行器。

[Cloudflare 官方限制](https://developers.cloudflare.com/durable-objects/platform/limits/)
列出 DO 默认每请求 30 秒 CPU、SQL 单行 / 字符串 / BLOB 最大 2 MB。
解析后的 1 MB 整批限制为预览行的原文、摘要和 UTF-8 / JSON 开销留出空间；本地 Miniflare
不能证明真实生产请求的 CPU 配额或大陆网络表现，实际文件仍须先预览验收。

迁移顺序为 001–007。已执行 007、未执行 006 的数据库会只补跑 006；不要将只支持 006
的旧导入分支直接部署到线上。保留原 Worker、SkarmaSpace 和空间标识，发布前备份并对账。
