## 复现、修复与漏测原因

- 上一版回执只有文字；能从页面其他位置进入总结，并不能替代回执旁的操作。现在回执按钮直接打开刚保存的计划 ID，另一个待总结计划保持原状态。当天已记录列表和跨日期补录的回执都已测试。
- 在旧版先新记困难和经验，再选实际目标和方法，两条知识仍保留空关联。正式提交在浏览器校验阶段被拦下，本机填写还在，服务器仍是原计划，跟进库中没有这两条。本次回归从这条顺序开始，并核对实际 PUT、共享快照、跟进列表及目标和方法详情。新条目默认跟随实际主目标及所选方法，手动调整关联后按手选值保存。旧草稿的空关联可点「关联本次目标和方法」补齐后原地提交。暂存总结中对已有条目的反馈现在也能在重开后保留，到正式提交再产生反馈记录。
- 旧浏览器测试特意断言目标页可继续干预草稿，近期专项则只在今天页检查有无重复。两者都没有带家庭及课堂草稿逐页检查。现将恢复入口限定在今天页，其他页面按用户点击的具体记录打开详情或整理。用同一个手机浏览器带着两类草稿检查目标、方法、记录两个视图、跟进及账号页，回到今天仍能继续。
- 截图中的提醒报错可用两条已从目标目录移除但保留历史的合成目标重现。首次读取提醒/复盘队列时遍历历史实体又查找有效目标，旧版返回 404。现在仅为仍在目录里的目标维护提醒。原有账号、历史、计划及目标移除标记都沿用原数据。没有读取设备中那次请求，不能由这些复现推断它曾成功入库。

## 自动复查

普通发布在切换流量前会运行手机浏览器端到端检查，一组失败即停止发布。验收用临时 SQLite 和合成家人，分别覆盖日常操作、迟到或丢失的保存回执、两类知识在不同页面的展示。今天提醒另有 Rust 旧资料回归。本机还复验家庭干预修订、并发版本和另一位家人接手的完整流程。运行方式见下方。

```sh
cargo build --locked -p skarma-api
npm run web:build
npm run test:prd-web -- smoke_prd_family_journey_web.py smoke_prd_family_submit_web.py smoke_prd_summary_repair_web.py
```

浏览器测试依赖见 `tools/browser-test-requirements.txt`，可通过 `CHROMIUM_EXECUTABLE` 指定 Chromium。当前本机 185 项 Rust、100 项客户端、TypeScript、Web 及 Wasm 构建通过。公开站点不运行合成写入。
