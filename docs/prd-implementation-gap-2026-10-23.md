## 需要优先解决的设计问题

1. **复盘证据缺口最大。** 目标有版本历史，但困难／经验是“当前结论＋状态”，没有每次尝试和反馈；改日期不能代替 PDCA 的 Check／Act。
2. **方法实际使用缺口影响均衡判断。** 机构课程有实际方法，家庭尚无；目标适用关系再丰富也补不出实际使用次数。沿用 T10，避免另建重复任务。
3. **老人流程的复杂度。** 当前虽只有课程／老师必填，整页仍展示目标、方法、问题等；“都可选”不等于“易用”。用渐进展开保留父母需要的关联能力。
4. **提醒对象不完整。** 已有目标弹窗和困难日期卡片要复用，补无日期默认、方法／经验、周期、下一步行动和共享状态。
5. **费用结算本期范围已收敛。** 只补课时核对、明细与月切换，不开发金额。老师名称变更不能导致漏课或重复计数，稳定身份需要明确迁移。
6. **排序和颜色不能暗示错误结论。** 少记录≠能力差，困难多的方法应优先检查而非推荐多用；用户已确认完成目标的方法靠后。

## 实施约束与后续顺序

本轮交付调研、PRD 草案、差距及讨论记录。R01–R14 的新增项属于后续候选实施范围；T35／T36 已完成的功能仍然完成，但不包含这次提出的完整周期复盘和轻量观察流程。

建议按照 PRD 第7节 A／B／C 分批；先评审引导问题、经验使用证据、目标量化方式和复盘闭环，再为每批建立独立验收与任务状态。用户已经确认的三项选择无需再次确认：

- 完成目标的方法靠后，有困难／停滞／少覆盖者优先检查。
- 课程只统计节数明细，金额线下算。
- 中短期隔周、长期／方法／经验每月、停滞困难每周，集中家庭周末，日期可改、可暂停。

当前阶段不改数据库或应用、不执行测试数据恢复、不发布、不访问生产业务数据。应用验收提交保持 `5eaa910`；原 T12 环境配置故障与本轮需求文档无依赖关系。
