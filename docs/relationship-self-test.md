# 目标、方法、经验与家庭干预关联自测

本轮按用户要求从空白数据开始，通过页面逐个创建，未使用真实业务数据，也未向生产站点写入。
应用逻辑未改动，对应实现仍为 `bcbed65`。

## 测试对象

两套独立空间分别执行同一流程：原生 Rust API + SQLite；真正 Rust Wasm Worker + Miniflare SQLite Durable Object。
后者的网页资源由本机同源网关提供，API交给真实Worker执行；不是线上Cloudflare部署验收。

| 对象 | 通过页面录入的内容 | 关系 |
| --- | --- | --- |
| 短期目标 | 【关联自测】主动表达需要 | 暂不关联上级 |
| 方法 | 【关联自测】视觉选项提示 | 明确选择该目标 |
| 独立经验 | 【关联自测】先等待，再提供提示 | 明确选择该目标及方法，无来源训练 |
| 家庭干预 | 【关联自测】家人一起练习选择物品 | 该目标为唯一主目标，先保存计划、再提交总结 |
| 总结生成的经验 | 【关联自测】两张选项有助于主动表达 | 默认该主目标，并选择该方法；来源为本次干预 |

每个空间最终是1个目标、1个方法、1条已完成训练、2条经验（独立经验与训练生成经验各1条）。
所有目标、方法、经验和计划／总结都由浏览器表单写入；API只用于读取结果并核对精确ID。
管理员仅在临时测试空间中建立，未获取真实管理员或账号数据。

## 核对结果

以下项目在两种后端均通过；使用390×844浏览器窗口。

| 检查 | 实际结果 |
| --- | --- |
| 目标页 | 显示方法、两条经验及这条相关训练 |
| 方法页 | 显示关联目标入口和两条经验 |
| 跟进页 | 两条经验分别显示正确目标和方法；独立经验没有虚构来源 |
| 训练来源 | 训练生成的经验可点击“查看来源训练”，返回对应计划与观察 |
| 训练详情 | 显示正确目标快照、计划、逐目标观察及训练生成的成功经验 |
| 记录页 | 家庭干预列表能找到同一条已完成记录 |
| 重复与串联 | 按返回的ID核对，无重复创建、错绑或串到其他对象 |
| 页面刷新 | 重新进入目标详情后，各项关联仍显示 |
| 另一浏览器会话 | 新登录的独立浏览器上下文能看到同一组关联 |
| 进程／模拟环境重启 | 停止、重新启动后，完整AppState与重启前逐项一致 |

`npm run test:relations`完成并退出0。没有为此重新运行无关功能或部署；原正式数据未改动。

## 复跑

使用已准备好的Rust／Node开发环境，先构建网页、原生API和Worker，再执行：

```bash
npm run web:build
cargo build -p skarma-api --locked
(cd crates/worker && worker-build --release)
npm run test:relations
```

脚本为两个后端分别建立全新的临时存储，完成后删除临时数据库并关闭服务。
合成截图和逐项结果留在Git忽略的`.local/relation-selftest-evidence/`；选定截图经检查后才进入文档产物目录。
