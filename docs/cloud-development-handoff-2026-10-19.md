## libp2p 调研最重要的结论

1. js-libp2p 官方已有 React Native / 原生 WebRTC 接入路线；当前 Expo 57 / RN 0.86 组合未做真机兼容验收。
2. 需要自行构建含原生模块的 App；不能把 Expo Go 或浏览器演示当作当前两端手机已经通过。
3. libp2p 是连接与传输层；本地业务数据库、增量日志、幂等、删除标记、冲突与恢复仍需开发。
4. 手机后台执行由系统调度。应承诺打开 App 时自动尝试同步、恢复后补传，不能承诺 iPhone 全天在线。
5. relay 转发实时流，不是离线信箱。用户允许长期在线家庭电脑保存变更并转交，因此手机之间
   无须同时在线；各手机需要能连接此节点。该节点必须实现持久应用同步，不能只开启 relay。
6. 原生通信不要求自有域名；跨网发现 / 穿透仍需可达节点。公共 relay 免费永久、稳定覆盖大陆尚未证实。
7. 家庭管理员授权设备；PeerId 本身不代表家庭成员权限。网盘备份使用加密版本包，恢复须校验并合并。
8. 先以每日上课记录验证双真机原型，再决定全系统改造。现有训练完成命令有跨表副作用，不能简单在多端重放。

这些是研究结论与拟议设计，**不是实现验收**。本次上传只接收材料，具体开发由用户在云端后续指示。
