# 规划总览与均衡覆盖

日期：2026-10-18。目的：安排训练前同时看到各个中短期目标的状态与训练分配，发现近期较少被关注的方向。均衡不要求所有目标次数相同，也不根据训练次数推断能力高低。

## 使用

底部“规划”、今天页“先看规划总览”、目标页及训练编辑中的“查看规划总览”均可进入。默认查看近 30 天的在用短期目标；可选择 7／30／90 天、全部记录、中期目标及包含归档目标。

- **训练分布环形图**：展示当前目标范围的目标覆盖次数，点击扇区或图例可筛选目标。最多单列六个目标，其余合并并可展开；零次目标仍在列表和未覆盖提醒中展示。
- **当前目标进展环形图**：展示人工确认的状态分布。未设置状态保留“待核对”；归档没有自动当作达成。当前数据没有量化能力达成率，不将次数或观察文字转换成百分比。
- **目标列表**：默认按所选时间内次数从少到多排序，同次数时较久未记录的在前。显示次数、最近训练日期、最近有内容的逐目标观察、达成标准和使用中途径数量。中期目标还显示当前下属短期目标的已达成／完成数量及比例环形图。
- **途径覆盖**：展示有明确使用中途径的目标数量、各途径的明确关联目标与经验条数，并可进入途径详情。当前没有每次训练实际使用途径的数据，因此不展示或推算途径训练次数。

从目标卡片“围绕此目标规划”可新建带有该目标的训练草稿；有当前草稿时显示“加入当前计划”，保留原内容、ID、版本和已有目标，不重复添加。待推进目标优先补主目标，已有主目标时补副目标；已达成、已完成或归档目标以复习角色加入。未确认的提交需先完成重试。加入只修改本机草稿，仍需明确保存或完成训练。

## 统计口径

| 信息 | 口径 |
| --- | --- |
| 日期 | 使用训练的业务日期（Asia/Shanghai），起止日均包含；7 天包括今天及前 6 天，全部记录截至今天 |
| 已完成训练 | 只统计 `completed`，排除服务端草稿、本机草稿和未来日期；一条训练 ID 只计一次 |
| 目标覆盖 | 一场训练覆盖两个目标，各目标各计一次；图中分母是目标覆盖次数之和，不是训练场数、分钟数或能力分数 |
| 中期覆盖 | 直接关联该中期，或训练时快照中的短期目标属于它；同一场同时满足多个条件仍只计一次 |
| 直接／下属短期 | 中期有直接目标明细时归入直接训练；仅通过下属短期覆盖时归入另一项，两项之和等于该中期次数 |
| 历史归属 | 优先采用当次 `goal_snapshot.parent_id`；后来调整当前父级不会搬移历史。旧记录没有快照时才使用当前已知关系 |
| 最近训练与观察 | 查找截至今天的全部已完成记录，不局限于时间窗口，标注日期；窗口内零次仍可看到较早的训练与观察 |
| 未覆盖提醒 | 当前范围内所选时间计数为零且仍需推进的活动目标；已达成、已完成及归档目标不参与提醒 |
| 状态与下属达成 | 使用当前目标状态和当前父子关系，不是窗口末尾的历史进度；归档本身不增加达成数 |
| 途径覆盖 | 当前目标与使用中途径的明确关联，重复映射到同一目标只算一个已覆盖目标；不经长期父级自动推断 |

训练图的百分比用于看分配，目标进展图的百分比表示各状态的目标数量占比。中期卡片上的短期达成比例只表示已确认达成的子目标数量；每个子目标难度和所需支持可能不同。

## 实现与验收

统计由共享 TypeScript 模块根据已登录空间的 `/api/state` 计算，原生 SQLite 和 Cloudflare 后端使用同一前端，不新增服务端接口或数据库迁移。图表使用 Expo SDK 57 所列的 `react-native-svg` 15.15.4，提供文字图例与可访问名称；本轮验证 Web，原生 App 仍待二期验收。

`npm run test:planning` 验证日期边界、去重、父子汇总、历史改父级、空空间、状态与途径映射。`npm run test:host` 包含 `smoke_planning_web.py`，用专用临时库验证真实 API 数据下的环形图、时间与目标筛选、途径详情、草稿保留、角色分配与刷新恢复；另验证大于六个目标的合并图例，以及 320／390／960 像素布局。截图保存在被 Git 忽略的 `.local/screenshots/planning.png`。
